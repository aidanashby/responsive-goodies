   one frontend feature is enabled.

   wp_add_inline_script in 'after' position exists anywhere in the codebase.

page via the $hook check in enqueue_admin_assets().

<task type="auto">
  <name>Task 1: Add transient guard to get_remote_version() in class-updater.php</name>

  <read_first>
  Read includes/class-updater.php in full. Locate get_remote_version() (private method).
  Currently it calls wp_remote_get directly with no caching. The check_for_update()
  method which calls it fires on the WordPress pre_set_site_transient_update_plugins
  filter — this runs on every admin page load.
  Also read get_changelog() in the same file — it also makes an uncached API call and
  should receive the same treatment with a separate transient key.
  </read_first>

  <files>includes/class-updater.php</files>

  <action>
  In get_remote_version():
  1. At the top of the method (before the wp_remote_get call), add:
       $cached = get_transient( 'rg_update_check' );
       if ( false !== $cached ) {
           return $cached;
       }
  2. After successfully extracting the version string from $data['tag_name'], before
     returning it, add:
       set_transient( 'rg_update_check', $version, 6 * HOUR_IN_SECONDS );
  3. The variable holding the extracted version (currently returned inline) must be
     assigned to $version first so it can be cached before return.
  4. The false return paths (is_wp_error, no tag_name) must NOT set the transient —
     failed API calls should not be cached.

  In get_changelog():
  Apply the same pattern with transient key 'rg_changelog_info' and TTL 12 * HOUR_IN_SECONDS.
  Cache the $changelog string before returning it. Do not cache on is_wp_error paths.
  </action>

  <files>includes/class-responsive-goodies.php</files>

  <action>
  Add a private helper method any_feature_enabled(): bool to the class:

    private function any_feature_enabled(): bool {
        $options = get_option( 'responsive_goodies_options', array() );
        $flags = array(
            'orphan_fix_enabled',
            'device_menu_enabled',
            'disable_hover_enabled',
            'prevent_scroll_enabled',
            'back_to_top_enabled',
        );
        foreach ( $flags as $flag ) {
            if ( ! empty( $options[ $flag ] ) ) {
                return true;
            }
        }
        return false;
    }

  At the top of enqueue_frontend_assets(), add a guard clause:
    if ( ! $this->any_feature_enabled() ) {
        return;
    }

  Do not change any other lines in enqueue_frontend_assets().
  </action>

  - includes/features/prevent-scroll/class-prevent-scroll.php — enqueue_styles() (check if scripts)

  Also confirm via grep -rn "wp_add_inline_script" includes/ returns zero results before
  applying defer — this was confirmed before planning but verify again.
  </read_first>

  <files>All five feature class files</files>

  <action>
  For every wp_enqueue_script call that enqueues a frontend (non-admin) script,
  change the 5th argument from true (in_footer boolean) to:
    array( 'strategy' => 'defer', 'in_footer' => true )

  Example transformation:
    wp_enqueue_script( 'handle', $url, array('jquery'), VERSION, true );
    → wp_enqueue_script( 'handle', $url, array('jquery'), VERSION, array( 'strategy' => 'defer', 'in_footer' => true ) );

  Do NOT apply defer to admin-side wp_enqueue_script calls (device-menu
  enqueue_admin_scripts() method — leave that as-is).

  Skip any feature class that only enqueues styles (wp_enqueue_style) and has no
  wp_enqueue_script calls.
  </action>

    - Admin script enqueue calls (device-menu admin scripts) are unchanged
    - php -l on each edited feature class passes
  </acceptance_criteria>
